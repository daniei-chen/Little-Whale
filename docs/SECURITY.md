# 安全说明：关于「报毒」这件事

> **一句话结论**：`a.gray.BulimiaTGen.f` 不是病毒，是安全厂商对「灰色软件」的**启发式聚类判定**。它命中的是我们曾经具备的「应用内下载并安装 APK」能力，而不是恶意代码。该能力已在 v0.0.6 中彻底删除。

如果你是在安装小鲸鱼时看到红色风险提示、或者被反诈中心电话核实，然后点进这个页面 —— 这份文档就是写给这个场景的。

我们尽量把话说清楚，包括对我们不利的部分。

## 为什么你的手机可能会提示风险

小鲸鱼的分发方式和绝大多数国内 App 不一样：

| 项目 | 大多数国内 App | 小鲸鱼 |
|---|---|---|
| 分发渠道 | 应用商店（华为 / 小米 / OPPO / 应用宝…） | **只有 GitHub Releases** |
| 签名 | 企业签名，商店做过完整性核验 | **个人开发者自签名** |
| 商店白名单 | 有（上架即等于通过一次审核） | **没有** |
| 厂商侧样本量 | 百万级安装，良性样本充足 | 小，尚未积累信誉 |

国产安全引擎（小米 / OPPO / vivo / 华为手机管家使用的病毒库，来源多为腾讯移动安全实验室）在判断一个安装包时，除了看代码，还会看**渠道、签名信誉、权限组合、能力画像**这几项。当一个包同时具备：

- 个人自签名证书，云端无历史信誉
- 未上架任何应用商店
- 具备「联网下载可执行文件 + 请求安装」的能力
- 功能面较宽（联网 + WebView + 文件写入 + 媒体下载）

它就会被聚进「灰色软件」这一类，给出 `a.gray.*` 的检出名称。这是**统计意义上的风险提示**，不是「我们扫描到了病毒行为」。

v0.0.5 的情况需要说清楚：这个包确实带了 `REQUEST_INSTALL_PACKAGES` 权限和应用内安装能力（自我更新）。所以我们不能简单地说「完全是误判」——**在特征层面，我们确实曾经符合那条规则**。整改就是把这部分删掉，而不是解释它。

## a.gray.BulimiaTGen.f 到底是什么

先拆名字：

| 片段 | 含义 |
|---|---|
| `a` | Android 平台 |
| `gray` | **grayware，灰色软件**。介于「正常软件」和「恶意软件」之间的分类，指行为合规性存疑的软件，不是病毒、木马、后门、勒索软件 |
| `BulimiaTGen` | 家族聚类名，由启发式规则给出 |
| `.f` | 同一聚类下的变体编号 |

关键点在这里：**`gray` 不等于「发现了恶意代码」**。它是厂商用一组特征（签名、渠道、权限、能力）打分聚类的结果。所以同一个名字会同时命中大量互不相关的小工具类应用——它们被聚在一起的原因是「画像相似」，而不是「都在做同一件坏事」。

### 为什么个人开发者特别容易命中

1. **没有商店白名单**：上架正规商店等于通过了渠道审核，引擎会默认给一定信任分；GitHub 直发没有这一步。
2. **签名没有历史信誉**：新证书在云端是空档案，无法证明「这个开发者长期发布无害软件」。
3. **小团队没有议价能力**：企业遇到误报可以走商务申诉通道，个人通常只能填工单。
4. **功能越杂，聚集风险越高**：一个 App 同时联网、跑 WebView、下载文件、写相册，特征向量天然更接近推广类软件。

### 为什么「换个签名」没用 —— 我们的前车之鉴

v0.0.5 发布时，我们在发布说明里写过一句话：**「换成正规章书后就不会了。」**

这句话是错的。

当时的实际情况是：换成正式证书后大约 **1~2 天**内确实不再报——因为新包还没进入厂商的样本库和病毒库，属于「还没被扫到」，而不是「已经安全」。等病毒库更新、新包被采集到之后，同一套规则再次命中，`a.gray.BulimiaTGen.f` 又回来了。

一个月后我们收到了同样的报毒反馈，还有用户被反诈中心电话核实。

**换签名只是短期规避**：它改变的是「这个包的签名特征」，而规则看的是「签名信誉 + 权限组合 + 能力画像」的整体。只要下载安装 APK 的能力还在，换成什么证书都会被重新聚到同一类。真正的解法是**减掉能力 + 申诉加白 + 上架正规商店**，这也是 v0.0.6 之后我们做的事。

> 补充一句免得误会：v0.0.6 确实又换了一次证书，但原因是旧私钥已经丢失、没法继续发版，**不是为了绕开检测**。本节结论不变——能不能不被报毒，取决于删掉了什么能力，而不是换了什么证书。

## 我们怎么自查的

我们解包了自己发布的 APK，做了一次只读静态取证（不修改、不重打包），并把结论全部公开。下表的数据都可以用文末命令复现。

被检样本：`xiaojingyu-0.0.5-arm64-v8a.apk`
SHA-256：`5b1d0b2ebb2128e220e4d0b0a660afafc16782e71b49b693cc7e5cba0154eafc`

| 查什么 | 结果 |
|---|---|
| 有没有广告 SDK | **没有**。友盟、广点通、穿山甲、Sigmob、Mintegral、AppsFlyer 等特征字符串全部 0 命中 |
| 有没有统计 / 埋点 / 崩溃上报 | **没有**。只有本地错误日志，不上传 |
| 有没有热更新 / 动态加载 DEX | **没有**。`DexClassLoader`、`PathClassLoader`、`InMemoryDexClassLoader` 全部 0 命中 |
| 有没有执行系统命令 | **没有**。`ProcessBuilder`、`dalvik.system.*` 0 命中；`exec` 相关字符串全是 `execute` / `Executor` |
| 有没有加固壳 | **没有**。`lib/arm64-v8a/` 下只有 Flutter 引擎、Dart AOT 业务代码和依赖库的原生 so |
| 能不能被调试 | **不能**。未声明 `debuggable`，APK 内无 `kernel_blob.bin`，确认是 release AOT 构建 |
| 应用自己写了多少原生代码 | **1 个类**：`cn.flashsave.flashsave.MainActivity` |

DEX 里到底有什么（共 1152 个 `class_defs`，其中只有 156 个带可读包名，其余全是 R8 生成的短名类——这本身就说明混淆和收缩早就开着）：

| 类名前缀 | 类数 | 是什么 |
|---|---:|---|
| `org/chromium/*` | 58 | AndroidX WebView 支持库（解析靠内置 WebView） |
| `androidx/*` | 45 | AndroidX 基础库 |
| `io/flutter/*` | 34 | Flutter 引擎 |
| `com/github/dart_lang/*` | 12 | `path_provider` 带入的通用 JNI 桥（v0.0.6 已移除） |
| `android/*` | 6 | Android Framework 引用 |
| `cn/flashsave/*` | 1 | 应用自身唯一的原生类 |

**结论**：这个包的能力面只有四项——联网（HTTPS）、用内置 WebView 渲染平台页面、下载媒体文件、把媒体写进相册。它没有下载执行外部代码、读写其他应用数据、后台静默推送、采集设备信息的能力。

它确实做错了一件事：**它把自己做成了可以给自己装更新的 App**（下载 APK + 请求安装）。这条能力在安全扫描里，与推广 / 捆绑类软件的特征完全重合。这是我们认定问题成因的地方，也是 v0.0.6 要删掉的东西。

## v0.0.6 做了什么整改

| # | 改了什么 | 为什么这对你更安全 |
|---|---|---|
| 1 | **彻底移除应用内 APK 下载与安装**：删除 `REQUEST_INSTALL_PACKAGES` 权限、`FileProvider`、`file_paths.xml`、安装器原生通道与 Dart 封装 | 应用从此没有「安装别的东西」的能力。即使 App 本身被攻破，也无法拿安装权限做任何事 |
| 2 | **更新改为打开浏览器下载页**：只提示有新版本，下载与安装交给系统浏览器和系统安装流程 | 安装包的来源与完整性由系统核验，不再经过我们的 App。App 不再写任何 `.apk` 文件 |
| 3 | **全面禁止明文流量**：`usesCleartextTraffic="false"` 且 `network_security_config` 中 `cleartextTrafficPermitted="false"` | 所有流量强制 HTTPS，公共 WiFi / 运营商链路无法注入或篡改内容（v0.0.5 是全量放行 HTTP） |
| 4 | **`allowBackup` 改为 `false`** | 解析历史不参与云备份，不会进任何云端副本 |
| 5 | **移除通用 JNI 反射桥**：把 `path_provider_android` 固定到不含 `dart_lang/jni` 的版本，APK 里的 `com/github/dart_lang/*`（含 `JniPlugin`，共 12 个类）与 `libdartjni.so` 都没有了 | 少一条「能加载任意 Java 类、调用任意方法」的通用反射通道，同时也少一个被特征规则误伤的面 |
| 6 | **ABI 收口为 arm64-v8a**：v0.0.5 声称支持三个 ABI，但 `armeabi-v7a`、`x86_64` 目录里没有 Flutter 引擎库，32 位机和模拟器装上会直接崩溃 | 这不算安全问题，但是个真缺陷，一并修了：现在 `native-code` 只有 `arm64-v8a`，不会再出现「装上了却闪退」 |
| 7 | **权限收敛到最小集**：只保留 `INTERNET`、`ACCESS_NETWORK_STATE`、`WRITE_EXTERNAL_STORAGE`（仅 Android 9 及以下）；另有一条 androidx 自动注入的自定义权限，只用于约束本应用内部广播，不授予系统能力 | 安装时不再索要高敏感权限；Android 10+ 甚至不需要存储权限 |
| 8 | **更换发布证书 + 签名升级为 v2 + v3**：旧证书私钥已不可用，只能启用新证书 | 发版能继续；签名符合当前最佳实践。**代价：必须卸载旧版才能装 v0.0.6** |

一句话总结：**v0.0.5 唯一符合「高危画像」的能力是自我更新，v0.0.6 把它连根删掉了，不是关掉开关。**

唯一的代价是：更新不能带进度条了，点了会跳到浏览器。我们认为这个交换值得。

不要用第三方网盘、群文件、他人转发的 APK。任何转发者都可以往包里塞东西，而签名会因此改变（见第 2 条）。

**2. 核对哈希与签名**

- 文件 SHA-256 应与 Release 说明或 `docs/SAFE-INSTALL.md` 中列出的值**逐字符一致**
- 签名证书 SHA-256 应为：`f2c266e8fc8bacdc7aaab93eb14638222d2f2f95d03d174fe503b49c55823827`（v0.0.6 起；旧版本的证书指纹已作废）

```powershell
# Windows：应输出 ACDBD2D18A28EF8D9327ECD65941AC860B255121026D2383EACA22B9D538FB90
Get-FileHash .\xiaojingyu-0.0.6-arm64-v8a.apk -Algorithm SHA256
```

**3. 安装前可以断网试一次**

小鲸鱼的解析功能需要联网，但**启动和界面本身不需要**。如果你只是先验证「这 App 装完会不会乱来」，可以：

1. 开飞行模式
2. 安装并打开
3. 看它是否要求额外权限、是否弹出奇怪的页面

正常情况下它只会安静地显示首页。确认没有异常再联网使用。

备用机、旧手机、或者 Android 模拟器（API 24 以上，带系统 WebView）都行。用一段时间没问题再装到主力机。

如果你在安装时看到它索要短信、通讯录、位置、应用列表、通知使用权、无障碍服务——**这不是我们的版本**。小鲸鱼只声明了三个系统权限（联网、网络状态、仅旧系统使用的写入存储），另有一条 androidx 自动注入的自定义权限，**没有一条是敏感权限**。看到别的，请立刻停止安装并告诉我们。

## 如果仍然被拦截，怎么办

### 方案一：忽略风险继续安装（推荐，前提是你已核对哈希与签名）

MIUI 的拦截弹窗不是硬性阻止，它给了继续的入口：

1. 弹窗底部点「继续安装」或「仍要安装」（部分版本在右上角「更多」里）
2. 二次确认页勾选「我已了解该应用存在风险」→ 点「仍然安装」
3. 安装完成后，若手机管家在病毒扫描里把它列为风险，选择「忽略」或加入信任

逐步操作路径（含不同 MIUI 版本的差异）见 [SAFE-INSTALL.md](./SAFE-INSTALL.md)。

### 方案二：把应用加入信任 / 关闭安装监控

- **手机管家** → 右上角设置 → 找到「安装监控」或「安全检测」相关开关 → 关闭（路径随版本变化）
- **设置 → 应用设置 → 应用管理 → 小鲸鱼 → 权限**：确认没有任何多余权限
- 若系统反复弹窗，可在「手机管家 → 病毒扫描 → 结果页」对单项选择信任

> 提醒：关掉安装监控会降低这台手机对其他未知来源 APK 的防护。**只在你能确认包来源的情况下这么做**，装完可以考虑开回来。

### 方案三：提交误报申诉

这是最能帮到后来者的做法，也是我们希望更多人做的：

1. 在腾讯手机管家内找到「软件误报申诉」入口（一般在「我的 → 帮助与反馈」，或官网 <https://m.qq.com/> 的服务入口），或把 APK 上传到哈勃分析系统 <https://habo.qq.com/> 做公开复核
2. 附上本仓库链接：<https://github.com/daniei-chen/Little-Whale>
3. 附上报毒截图与检出名称 `a.gray.BulimiaTGen.f`
4. 可直接复制 [`docs/COMPLAINT-TENCENT.md`](./COMPLAINT-TENCENT.md) 中的内容填写

样本量足够时，厂商才会重新评估这一类特征。个人开发者的申诉，很大程度上靠用户一起提交才有分量。

### 关于「国家反诈中心来电」

这是很多人最紧张的一点，说清楚：

- 反诈中心的核实电话，通常发生在**系统上报「安装了非应用商店渠道的高危安装包」之后**，属于例行风险核实流程
- 它**不代表你涉案、也不代表你被立案**。反诈中心的工作是提醒你别被骗（不要转账、不要给验证码、不要点陌生链接）
- 你只需要如实说明：从 GitHub 开源项目下载、开发者是个人、应用功能是保存视频
- 如果你确实担心，可以按方案一卸载，等我们上架正规商店后再装

我们理解这种体验很糟糕。这件事的根源是我们的分发方式（GitHub 直发 + 自签名），整改与申诉就是在解决它。

## 我们不承诺什么

为了不给你错误预期，这几点必须写清楚：

1. **不承诺「以后永不再报毒」**。代码层整改能消除已确认的高权重特征（自我更新能力），大幅降低命中概率，但**最终是否报毒取决于厂商病毒库的规则和样本积累**，不由我们决定。
2. **不承诺「换版本就一定不报」**。新版本刚发布时可能短暂不报，那只是还没进样本库，不代表已经通过判定。
3. **根治需要两件事**：向厂商提交申诉加白，以及上架正规应用商店（获取渠道白名单）。前者已在进行，后者是我们的计划。
4. **不上架商店之前，这套提示大概率还会零星出现**，尤其是病毒库大版本更新之后。

如果你无法接受这种不确定性，**完全建议你等我们上架商店后再使用**。这是合理的判断，不是不支持我们。
